# KV M3U 缓存方案

## 概述

通过预生成 M3U 订阅文件并存入 KV 缓存，大幅降低 D1 数据库写入消耗，同时统一播放验证逻辑。

## 问题背景

### 当前架构问题

1. **M3U 每次实时生成**：用户下载 M3U 时，每个频道都执行一次 `INSERT` 创建 IP 直连播放链接
2. **1000 频道 = 1000 次数据库写入**：对 D1 数据库造成大量写入压力
3. **IP 绑定限制复杂**：需要在播放时实时验证 IP，并维护 IP 列表
4. **广告触发逻辑分散**：`code_expired`、`code_unauth`、`copy_link_normal` 等多种操作类型难以统一管理

### 免费额度消耗分析

| 操作 | 消耗 | 说明 |
|------|------|------|
| 生成 M3U（1000频道） | 1000 次 INSERT | 每个频道创建 ip_play_links 记录 |
| 播放验证 | UPDATE 查询 | 更新 used_ips 列表 |

## 解决方案

### 核心思路

1. **预生成 M3U**：定时任务生成通用 M3U 订阅文件，存入 KV
2. **统一播放验证**：播放时检查 KV key 是否存在，不存在则触发对应广告
3. **简化广告逻辑**：通过 code 前缀（`vip_`、`free_`、`fav_`）区分触发不同广告

### 方案优势

- **M3U 下载 = KV 读取**：0 数据库写入
- **统一过期控制**：通过 KV TTL 控制有效期
- **简化广告管理**：3 种操作类型覆盖所有场景
- **保留权限控制**：订阅码有效期和 IP 限制仍在获取 M3U 时验证

## 目标

1. M3U 下载实现 0 数据库写入
2. 统一卡密订阅、免费订阅、收藏下载的 M3U 获取逻辑
3. 通过 KV TTL 控制播放链接有效期
4. 简化广告操作类型，便于管理
5. 保留现有的订阅码权限控制（有效期、IP 限制）

## 影响范围

### 需要改动的模块

- `handlers/sub.js` - VIP 订阅逻辑
- `handlers/freesub-api.js` - 免费订阅逻辑
- `handlers/live.js` - 播放验证逻辑
- `handlers/scheduler.js` - 定时任务
- `pages/favorites-page.js` - 收藏下载
- `database.js` - 广告操作类型管理
- 管理后台 - 设置项和广告配置

### 需要废弃的模块

- `/api/play/link` 接口
- IP 直连播放链接相关逻辑
- 旧广告操作类型（`code_expired`、`code_unauth`、`copy_link_normal`、`copy_link_ip_limit`）

## 风险评估

### 低风险

- 定时任务预生成 M3U，KV 存储量可控
- M3U 内容为通用格式，不包含敏感信息
- 旧用户在过渡期内仍可使用旧 M3U，过期后自动失效

### 需要关注的

- M3U 预生成耗时（需评估 10000+ 频道的处理时间）
- KV 存储配额（需确认 Cloudflare KV 存储限制）
- 过渡期用户引导（旧 M3U 过期后需要用户重新下载）
